# Engineering gates

All automated and manual engineering tests for M0–M8 must run on localhost, using isolated local services, synthetic fixtures and local mail/webhook receivers. This includes API, database/migrations, browser/widget, accessibility, RAG, security, restore and rollback checks. CI must use services local to its runner. Never target production, staging or external customer systems with tests; report any required external-provider verification as blocked until an explicitly authorized alternative is agreed. Real pilot observation is evidence gathering, not permission to run tests against customer systems.

Every milestone M0–M8 must have its own `codex/` branch, scoped commits and at least one milestone PR. After local checks and independent review, commit only the milestone's intended files, push its branch and create/update its PR. Include milestone/task IDs, acceptance evidence, exact localhost commands/results, residual blockers and rollback notes; record commit SHAs and PR URL in the existing roadmap/state. The user's workflow instruction authorizes these milestone commits and PRs. A milestone cannot be marked complete without its commits and PR recorded. Merge and production deployment remain separate actions and are not authorized by this rule.

For each scoped task: inspect active handlers and schema; define acceptance; reproduce baseline; add a regression when logic/security is involved; make the smallest correct change; run relevant tests; independently review high-risk changes; verify integration; preserve raw evidence; update the existing roadmap task. Compiling alone never closes a milestone.

Use root `npm test` and `npm run build` as baseline checks. Add targeted API/tenant/role, transaction/migration, portal, browser/axe and RAG checks only for the affected surface. Migration/authorization tests use synthetic tenants and an isolated DB, never inherited production `.env`. There is currently no worker test script. Browser and eval setup commands are documented in [evaluation-testing.md](evaluation-testing.md); offline transport smoke is not RAG correctness evidence.

M0 requires fixtures with records, negative authorization tests and the 27-route browser matrix. These business regressions are future M0 work, not implemented by environment setup. M1 requires independent security review. M2 requires visible loading/error/empty/success states, direct URLs, 390/768/1440 viewport behavior, keyboard and axe. M3–M6 need full producer/consumer behavior, not just saved configuration. M7 requires restore and rollback in isolation and final CI evidence. M8 is a real pilot decision.

Record command, exit code, version, environment, assertions, limitations and reviewer. Store only sanitized output. Existing deploy workflow has no pull-request test job; a separate non-deploying development check workflow is provided. Repository branch protections are remote settings and remain unverified. Never claim enforcement by documents alone.
