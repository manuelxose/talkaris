# Synthetic recovery checks

There is no production backup procedure here. A container can have host mounts and system access, so the earlier production-shaped backup prototype and its fixed-path tests were removed. Production requires an independently verified writer fence, interruption recovery, off-server storage, and full restore rehearsal before any release gate can pass.

`encrypt.sh` copies a fixed set of regular backup files into a private staging directory, rejects unexpected entries and checksum manifests, verifies the staged hashes, and encrypts that snapshot to an independently verified public-key fingerprint. It does not establish that the input was a coherent recovery point, copy the ciphertext off-server, or validate a remote restore. Files and ciphertext remain sensitive and must be protected. `encrypt.test.sh` uses a unique temporary directory and disposable passphrase-protected keys; its round-trip and inventory tests run in CI.

Before a real off-server copy, create a dedicated receiving key, protect its private key and preserve a separate secure offline copy with recovery instructions. Independently verify the public-key fingerprint, transfer only ciphertext, compare its hash across hosts, and decrypt and verify the embedded hashes in an isolated environment. Exercise private-key recovery from the offline copy independently of the receiving workstation. A workstation copy alone is not proof of durable backup.

`application-restore.test.ps1 -AppImage <image> -SnapshotManifest <manifest>` runs only the previously recorded synthetic M0 image and verifies both its immutable image ID and every file in its recorded source snapshot manifest before building. The recorded manifest is `evidence/talkaris-m0-75843624-a14/tree.sha256` from the original local M0 run, not a production release attestation. The test uses unique disposable containers with network mode `none`, synthetic credentials and a clean PostgreSQL client environment. It restores a synthetic dump and filesystem archive, then checks the API, a restored upload, login, widget, portal and a local ingestion job. It measures restore plus checks. It does not restore production systemd, Nginx or TLS, establish production artifact provenance, validate production recovery or prove off-server storage. This local-image rehearsal is not yet run in CI.
